# Skill Magnet：Astra管理・Terra実装 指示書

## 1. 役割と目的

ユーザー指定の分担は「脳はAstra、手は別モデル」。管理担当をGPT-6 Astra、実装WORKERをGPT-5.6 Terraとする。これはOpenAIの必須仕様ではなく、この作業の役割分担である。モデル選択だけで品質を保証しない。

- Astra：事実確認、原因の切り分け、変更仕様、受入条件、差分レビュー、最終判定を担当する。
- Terra：Astraが根拠付きで確定した、限定範囲のコード変更と指定テストを担当する。問題全体を丸投げしない。
- 同時に書き込むWORKERは1つ。AstraはWORKERの担当ファイルを並行編集しない。
- 現在の担当モデルを確認する。Astraでない管理担当はAstraとして判断したと偽らず、モデル選択が必要なことを明示する。

目的はWindows Explorer右クリック起動と関連終了・復旧の欠陥を、原因を確認した最小変更で修正すること。文書作成や単体試験だけを製品完成としない。

## 4. AstraからWORKERへ渡す単位

実装着手前に、Astraが次の項目を埋めた作業票を渡す。未確定原因の解決全体をWORKERへ委譲しない。原因未確定なら先に読取専用の調査票を渡す。

```text
作業ID：
対象の失敗：
確認した事実と証拠ファイル：
原因仮説／反証条件：
許可する変更ファイル・関数：
変更内容と変更しない動作：
修正前に失敗する再現方法：
修正後の期待結果：
異常系・中断・再試行の検証：
実行するテストコマンド：
禁止する変更・外部操作：
返却物：差分、実行結果、未確認事項
```

Terraは範囲外の原因や変更が必要と判明したら、証拠と必要な追加範囲をAstraへ返す。勝手に仕様変更、テスト条件緩和、例外握り潰しをしない。

## 5. 実行順序

1. Astraが現状差分を製品・collector・test・文書に分け、確認済み／仮説／未確認を整理する。
2. 旧root問題の既存probeと回帰試験を確認する。既存証拠で足りる調査を最初から繰り返さない。
3. 次の失敗箇所を1つに絞る。クリック未到達、callback不実行、callback後の残存、処理中workerを別仮説にする。
4. 必要な観測だけを追加する。画面名だけで同一対象とみなさず、PID・HWND・対象関係・必要な時刻を確認する。個人情報を公開ログへ混ぜない。
5. Astraが作業票を確定し、Terraへ限定実装を依頼する。
6. Terraが最小差分と実動作試験を返す。ソース中に文字列があるだけのテストをUI動作の証明としない。
7. Astraが差分と証拠をレビューする。テストを通すために対象判定を弱めていないか、既存保存・復旧・排他制御を壊していないかを確認する。
8. 局所試験が安定してから候補をbuild・導入し、source／wheel／導入runtimeの一致を確認して正式Explorer試験へ進む。失敗原因未確定のままbuildと導入を反復しない。
9. 正常起動だけでなく、連続投入、処理中終了、エラーからの復旧、再起動後の再試行を検証する。実行できない項目は未確認とする。
10. 原因調査書・対応報告・release証跡を実測結果で更新する。既存の承認範囲を確認して公開操作へ進み、CIやfieldの不合格を迂回しない。

## 6. 不変条件

- `SKILL.md`を`.codex/skills`、`.agents/skills`、`.claude/skills`へ新たに常設しない。
- 登録元、対象プロジェクト、成果出力先、一時領域、GitHub参照を混同しない。
- 元のスキルフォルダーを変更しない。既存の利用者データを復旧名目で削除しない。
- エラーは原因、現在状態、利用者が実行できる次の操作を示す。汎用エラーへ隠さない。
- リトライで二重登録・二重送信しない。未マージは故障ではなく待機状態として扱う。
- collectorの誤操作と製品の欠陥を分離する。同一PIDだけでクリック対象の正当性を保証しない。
- テストの無効化、成功値の捏造、過去版の実機証拠流用を禁止する。
- 無関係なリファクタリング、強制reset、無断の広範囲cleanupを禁止する。

## 7. 完了判定

| 段階 | 必要な証拠 |
|---|---|
| 原因確定 | 再現条件、反証結果、原因と症状の対応 |
| ソース修正 | 最小差分、修正前後比較、関連回帰試験の実結果 |
| 導入確認 | 対象source、成果物、実際のimport先・runtimeの対応 |
| 実機確認 | Explorer経由の正常・異常・復旧操作と証跡 |
| 公開完了 | 承認範囲内のcommit／push／CI／merge状態 |

下位段階だけで上位段階を「完了」と報告しない。全体試験は明示したソースをimportして実行し、件数・終了コード・失敗を記録する。過去の試験件数を転載しない。
