# エラー特定性欠落と日常利用フロー阻害の原因調査報告書

作成日：2026-09-07  
対象モジュール：`src/skill_magnet/ui.py`, `src/skill_magnet/library_ui.py`, `src/skill_magnet/core.py`

---

## 1. 概要と課題の提起

利用者がSkill Magnetの日常利用フロー：
> 1. フォルダーで右クリック → 「Skill Magnet」を選択
> 2. スキル／スキルパック：24個の登録済みスキルから選択
> 3. AIランタイム：Codex / Claude を選択
> 4. 依頼内容：目的を入力
> 5. 「起動」ボタンを押す

を実行する過程、あるいはエラー発生時において、以下の重大な設計上の問題が確認された。

1. **エラー特定性の欠落（エラーコード・詳細情報の非表示）**:
   - 処理失敗時や検証エラー時に表示されるダイアログに、一意のエラーコード（例: `SM-E101`等）や例外クラス名、WinError等の詳細な障害情報が表示されず、一般的な固定文章（「処理に失敗しました」「実行できませんでした」等）に丸め込まれていた。
   - このため、障害発生時に利用者が「何のエラーが起きたのか」を一目で特定できず、開発者側へ報告・特定することも困難になっていた。
2. **日常利用フローからの逸脱・管理動線の混在**:
   - スキルの実行を目的としたメイン起動画面（`show_context_selection`）に、開発・管理用の「Library Manager」および「このフォルダーのスキルを登録」ボタンが同等の扱いで配置されていた。
   - これにより、右クリック対象フォルダー（例: `Desktop`）が登録元フォルダーとして自動代入された管理画面へ誘導され、「日常利用の完結」を妨げていた。

---

## 2. 根本原因の分析

### 原因A: `context_failure_surface` におけるエラーコード体系の欠落

`src/skill_magnet/ui.py` の `context_failure_surface` および `context_failure_message` では、例外オブジェクトを受け取りながら、次の構造で整形していた：

```text
実行できませんでした

原因
選択したAIのverification processを開始できませんでした。

未実行・未確認の範囲
依頼実行、スキル受入確認、結果保存は完了していません。

次の操作
選択したAIのインストールと起動状態を確認してから再実行してください。
```

- **問題点**:
  - エラーを識別するコード（Error Code / ID）の項目が一切存在しない。
  - `_LaunchFailed`, `_RuntimeFailed`, `SkillMagnetError`, `OSError` などの型情報や内部メッセージが、固定の日本語テンプレートによって置換または切り詰められていた。
  - `run_context_background`（バックグラウンド検証処理）で例外が発生した際も、単に `処理に失敗しました\n\n{error}` と表示されるだけで、どのようなコンテキストで起きた障害なのかの体系的コードが存在しなかった。

### 原因B: 例外型とエラーコードのマッピング未定義

システム内で発生する例外（AI起動失敗、受入失敗、設定不正、ワークスペース不整合、OS権限エラー等）に対して、共通の識別識別子（Error Catalog）が整備されていなかった。

---

## 3. 解決方針と改修計画

### 対策1: エラーコード体系（`SM-E...`）の策定と導入

以下のエラーコード体系を定義し、すべての失敗サーフェスに明示する：

| エラーコード | 識別名 | 発生原因 |
|---|---|---|
| `SM-E101` | `AI_LAUNCH_FAILED` | AIエージェント（Codex/Claude）の起動・プロセス開始失敗 |
| `SM-E102` | `AI_RUNTIME_FAILED` | AIエージェントの検証プロセスが完了前に異常終了 |
| `SM-E103` | `ACCEPTANCE_FAILED` | 実行結果がスキルの受入条件を満たさない |
| `SM-E104` | `CLEANUP_FAILED` | 一時成果物の安全な後始末に失敗 |
| `SM-E105` | `OUTPUT_FAILED` | AIの出力形式が検証不能または不正 |
| `SM-E201` | `MENU_REINSTALL_REQUIRED` | メニュー設定の不一致による再登録要求 |
| `SM-E202` | `SELECTION_INVALIDATED` | 選択画面起動後の構成変更による無効化 |
| `SM-E203` | `CONFIG_INVALID` | 設定JSONの破損または構文不正 |
| `SM-E204` | `WORKSPACE_INVALID` | 対象フォルダーが存在しない、またはアクセス不能 |
| `SM-E205` | `TRANSACTION_INTERRUPTED` | ライブラリ更新トランザクションの中断 |
| `SM-E301` | `FILE_NOT_FOUND` | 指定された実行ファイルやパスが見つからない |
| `SM-E302` | `PERMISSION_DENIED` | ファイルやディレクトリのアクセス権限不足 |
| `SM-E303` | `OS_ERROR` | Windows / OS API レベルのシステムエラー（WinError含む） |
| `SM-E999` | `UNEXPECTED_ERROR` | その他の予期しない例外 |

### 対策2: ダイアログ出力フォーマットの強化

`context_failure_message` を改修し、画面およびログに必ず以下を出力する：
```text
[タイトル]

エラーコード
SM-Exxx (<識別名>)

原因
<原因の説明文>
[詳細: <例外クラス名>: <詳細メッセージまたはWinError>]

未実行・未確認の範囲
<未完了範囲>

次の操作
<推奨アクション>
```

### 対策3: メイン画面（ランチャー）の日常利用フロー優先化

- メインランチャー起動画面において、日常の4ステップ（スキル選択・AI選択・依頼入力・起動）が最も視認しやすく迷わないレイアウト・フォーカスを確保する。
