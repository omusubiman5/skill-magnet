# 標準Skill登録拒否の原因調査

## 事象

右クリックから`android-cli`を登録すると、`Skill android-cli must define trigger and boundary`が表示され、Library Manager本体が空のまま停止した。`android-cli/SKILL.md`には有効な`name`、利用場面を説明する`description`、具体的な本文が存在する。

## 原因

直接原因は`validate_library`が`SKILL.md`全文を正規表現で検索し、`trigger`／`boundary`または限定的な日本語表現の両方を含まなければ拒否していたことである。これは標準Skillの必須構造ではない。

根本原因は、意味上の選定基準を機械的な固定語契約へ置換した設計判断である。前回のCMA004対応では、拒否された一例の文言を許可リストへ足したため、誤った前提を除去できなかった。

## 失敗TREE

- 固定語による意味判定
  - 英語の別表現を使う標準Skillを拒否する
  - 日本語以外のSkillを語彙ごとに取りこぼす
  - 見出しを設けずdescriptionへ利用場面を書くSkillを拒否する
  - 固定語だけを含み実質的な指示がないSkillを誤って許可する
- 最初の兆候だけを修正
  - CMA004の表現だけを許可する
  - 別Skillの`android-cli`で同じ原因が再発する
  - 単体成功を全候補成功と誤認する
- UI開始時に例外が発生
  - inventory描画前にウィンドウが空になる
  - 利用者にはどのファイルを直すべきか分からない
  - 再試行しても同じ独自条件で停止する

## 判断

固定語の追加では修正にならない。登録時は検証可能な標準構造だけを検査し、意味上の適用条件・境界は実行時のSkill選定へ委ねる。これにより標準Skillを改変せず登録できる。
