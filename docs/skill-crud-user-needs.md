# Skill CRUD ユーザーニーズ

## 目的

Library Managerを「作成済みスキルを一度登録するだけの画面」ではなく、GitHubを正本とするスキルライブラリを継続管理できる画面にする。

## 利用者がしたいこと

1. 登録済みのスキルパックと、その中のスキルを名前で一覧確認したい。
2. 内部IDやcatalog JSONを知らなくても、フォルダーを選ぶだけで新規登録したい。
3. 修正済みの`SKILL.md`を選び、既存スキルを差分更新したい。
4. 不要なスキルまたはパックを選んで削除したい。
5. 同じスキル集合のパックを誤って重複登録・重複表示させたくない。
6. 登録・更新・削除を送信前に確認し、GitHub PRとして公開したい。
7. PRのマージ後は、追加・更新・削除後の状態が右クリックメニューへそのまま反映されてほしい。
8. 途中で失敗しても、再試行・保留・安全な破棄のいずれかを利用者が選べるようにしたい。

## CRUDの意味

| 操作 | 利用者から見た意味 |
|---|---|
| Create | 新しいスキルまたはパックのフォルダーを登録する |
| Read | 登録済みpack→skillの階層、表示名、説明、所属を確認する |
| Update | 選択した既存スキル／パックを、同じIDのフォルダー内容で置き換える |
| Delete | 選択したスキル／パックをcatalog、INDEX、ファイル、マージ後のメニューから除く |

## 受入条件

- CRUDは1つのLibrary Manager画面で行える。
- IDの手入力を要求しない。選択対象とフォルダー内容からIDを決める。
- 更新対象と選択フォルダーのIDが違う場合は、別物への誤更新として送信前に止める。
- 依存されているスキルは削除できず、依存元を具体的に表示する。
- 最後のpack／skillを削除して公開不能な空ライブラリにはしない。
- 同一スキル集合の別IDパックは新規登録時に重複として止める。
- 変更途中でvalidationに失敗した場合、catalog、INDEX、フォルダーを変更前へ戻す。
- 同じGitHub保管庫から消えたpackは、マージ確認後の有効化で右クリックメニューからも消える。
