# Windows版MVP キーボード操作テスト計画

## 対象と完了条件

対象は、ExplorerからSkill Magnetを起動した後の「スキル選択・依頼入力・実行」と「Library Managerでの登録・更新・削除・復旧」です。アプリ内ではマウス座標を合否判定に使いません。利用者がTab／Shift+Tab／矢印／Enter／Space／Escだけで目的を達成できた場合に合格とします。

Explorerの右クリック起動はOS連携の別試験とし、アプリ内キーボード操作と混同しません。試験用関数の直接呼出し、UI Automationの属性検査、座標クリックだけでは本計画を合格にできません。

## 正常操作

### AC-1：実行先とスキルを選んで依頼を渡す

**Given** ExplorerからSkill Magnetを開き、操作可能な初期フォーカスが表示されている

**When** Tab／Shift+Tabと矢印キーでスキルとCodexまたはClaudeを選び、依頼を入力してEnterまたはSpaceで実行する

**Then** 選択内容と依頼が指定したデスクトップアプリの新規タスクへ一度だけ渡り、Skill Magnetは処理中と結果を表示する

### AC-2：作成済みスキルを登録する

**Given** SKILL.mdを含むフォルダーから登録画面を開いている

**When** Tabで「登録」へ移動し、EnterまたはSpaceを押す

**Then** フォルダーを再選択させず登録し、一覧にスキル名と種類を表示する

### AC-3：登録済み項目を更新する

**Given** Library Managerの一覧に登録済みスキルまたはパックがある

**When** Tabで一覧へ移動し、矢印キーで対象を選択し、Tabで「選択項目を更新」へ移動してEnterまたはSpaceを押す

**Then** 選択した項目だけが更新対象となり、GitHubへの変更内容と処理結果が表示される

### AC-4：登録済み項目を削除する

**Given** Library Managerの一覧で削除対象をキーボード選択している

**When** Tabで「選択項目を削除」へ移動し、EnterまたはSpaceを押し、確認画面もキーボードで確定する

**Then** 選択した項目だけが削除対象となり、GitHubと一覧の結果が一致する

## エラーと復旧

### AC-5：無効な登録フォルダーから復旧する

**Given** SKILL.mdがないフォルダーから登録を開始している

**When** 登録操作をキーボードで実行する

**Then** 不足ファイルと選び直す方法が表示され、Enterで案内を閉じた後もTab操作を継続できる

### AC-6：通信またはGitHub処理の失敗から復旧する

**Given** 公開処理中に通信またはGitHub操作が失敗する

**When** エラー画面をキーボードで操作する

**Then** 再試行、状態を保存して戻る、または安全に閉じる操作を選べ、ソース編集・内部ID入力・lock削除を要求されない

### AC-7：処理中の連続投入を防ぐ

**Given** 登録または公開処理が進行中である

**When** EnterまたはSpaceを連続して押す

**Then** 同じ処理は一件だけ実行され、処理中表示が維持される

### AC-8：途中で閉じて再開する

**Given** 未完了の登録または公開処理が保存されている

**When** Escまたはウィンドウの閉じる操作で終了し、再度Library Managerを開く

**Then** 保存済み状態から再開でき、重複登録・重複PR・既存データの削除が発生しない

## アクセシビリティと操作一貫性

### AC-9：フォーカスが見え、循環する

**Given** Skill MagnetまたはLibrary Managerが表示されている

**When** Tabで最後の操作可能項目まで進み、さらにTabを押す。またはShift+Tabで逆方向へ移動する

**Then** フォーカスが常に視認でき、無効項目や読み取り専用の長文表示に閉じ込められず、操作可能項目を循環する

### AC-10：キーの役割が画面間で一致する

**Given** 通常画面、確認画面、エラー画面のいずれかが表示されている

**When** Enter／Space／Escを押す

**Then** EnterとSpaceは現在フォーカス中の操作だけを実行し、Escは破壊的処理を確定せず一段戻るか安全に閉じる

## 実行順序と証拠

1. ウィジェット単位で初期フォーカス、Tab順、Enter／Space、Esc、処理中の無効化を確認する。
2. 登録・更新・削除・復旧を、座標を使わないキー入力で局所確認する。
3. Explorer右クリック起動を一度だけ行い、起動後はAC-1からAC-10をキーボードで通す。
4. 合格後に既存release gateと台帳を現在の候補へ整合させる。
5. commit、push、CI、mergeの順に実行し、merge後のcommitと導入済み配布物の対応を記録する。

各試験は、候補commit、配布物SHA-256、開始状態、入力したキー列、観測結果、変更された対象、復旧結果を記録します。失敗時は同じ通し試験を反復せず、失敗したACと原因仮説に対応する局所試験だけを行います。

## 再試験規則

- 製品コードを変更した場合：変更したACの局所試験を先に行い、成功後にキーボード通し試験を一度行う。
- テストコードだけを変更した場合：製品の成功実績として数えず、そのテストが誤判定していた根拠を残す。
- 座標やカーソル位置だけで失敗した場合：アプリ内UXの不具合と断定せず、対応するキー操作試験で判定する。
- 同じ原因で二度失敗した場合：再実行を止め、原因・反証条件・次の局所検証を記録してから進める。

## 対象外

- マウス座標の一致をアプリ内操作の受入条件にすること。
- テスト収集器の一般化や新しい証跡基盤の追加。
- macOSをWindows版MVPの完了条件へ混ぜること。
- デスクトップアプリへ渡した後のAI回答完了をSkill Magnetの成功として扱うこと。
